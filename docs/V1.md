# v1.0 readiness

PeaProxy **v0.2.6** is already a shippable local gateway. A **1.0** tag is a honesty/quality cut, not a new OAuth program or a tray app.

Related: [PLAN.md](PLAN.md) (phases), [PROVIDERS.md](PROVIDERS.md) (adapters), [OAUTH.md](OAUTH.md) (liability), [COMPETITOR-WINS.md](COMPETITOR-WINS.md) (issue themes vs shipped), [HARNESS.md](HARNESS.md), [CONFIG.md](CONFIG.md).

## Already shippable (0.2.x)

Do not rebuild these for 1.0:

- Live catalog (`ListModels` source of truth; hide is listing-only; optional pin/rename)
- OpenAI `/v1/chat/completions` + Claude `/v1/messages` (true SSE) + Codex `/v1/responses`
- Vision-in Showcase (URL / upload)
- Official **API-key** adapters and hosted/local OpenAI-compat presets
- Subscription **OAuth** for Claude, Codex, Gemini/Antigravity, xAI, Kimi, Meta Muse — **ToS/ban risk**; authors not liable; keys remain official
- OS keychain / encrypted-file secrets (no plaintext tokens in YAML)
- Round-robin failover on 429/401 with 30s cooldown skip and Health UI
- Harness presets + `peaproxy clients verify [--chat]`
- Loopback default; LAN bind requires `--allow-lan` + admin token
- CLI + localhost UI only (**no tray, by design**)
- Settings, first-run Accounts CTAs, `config validate`, opt-in request inspector, persisted usage
- Tagged GitHub Releases (linux/darwin/windows, amd64+arm64)

Install: `go install github.com/ks1686/peaproxy/cmd/peaproxy@v0.2.6` or `@latest`.

## Known residuals (accepted in 0.2.x)

These are **not unmarked plan phases**. Call them out; do not hype them as done.

| Residual | Reality | 1.0? |
|---|---|---|
| Qwen consumer OAuth | Stub **not yet**. No CPA flow. Use `openai_compat` + a Qwen key. | **Do not block.** No new reverse-engineering unless a public flow exists. |
| Image-out | Catalog may tag `image_out`. Showcase gated. No `/v1/images/generations` proxy. | Optional. Ship 1.0 without it. |
| Claude Cloudflare 403 | Stock Go TLS. No uTLS / fingerprint spoofing. Prefer `adapter: anthropic` API key. | **Do not block.** Do not add uTLS for a 1.0 checkbox. |
| macOS / Windows tray | Not built. Locked: CLI + localhost UI. | **Won't do.** |
| Failover policies | Runtime is round-robin + cooldown. `fill-first` / `sticky` names are unused. Error-body inspection is incomplete. | Optional polish. |
| Amp WebSocket / `amp.url` | Custom URL chat-completions only. | **Won't do** as Amp management API. |
| Codex tools surface | Native pass-through for Codex OAuth; other adapters translate via chat (smoke-level). | Optional. |
| Embeddings / quota-remaining APIs | Not shipped. | Optional / later. |
| Copilot, Factory Droid, OpenCode Go sub | Not adapters. | Later, not 1.0. |
| GitHub Models | Retired 2026-07-30. | **Won't do.** |
| pea-pod.me page | Separate repo. | **Out of this repo.** |

## 1.0 cut checklist

A 1.0 tag is reasonable when **all** of the following are true. None of them require new OAuth reverse-engineering.

- [x] v0.2.6 product surface above is on `main`
- [x] Liability is documented in README, CLI, UI, and [OAUTH.md](OAUTH.md)
- [x] Docs match v0.2.6: README feature matrix, [PLAN.md](PLAN.md) phases, this file
- [ ] CI green on the revision that will be tagged
- [ ] Owner accepts the residual table (Qwen not-yet, image-out gated, stock TLS, no tray)
- [ ] Optional: refresh UI screenshots if Settings / Request log / onboarding should appear in README
- [ ] Optional: one **manual** OAuth smoke on a real subscription (cannot be CI). If Cloudflare 403, document “use API key” and still ship
- [ ] Tag **after** merge to `main`, not from a feature PR (`git tag -a v1.0.0` → GoReleaser)

## Won't-do for 1.0

- Menu bar / tray / TCC entitlements
- uTLS or TLS-fingerprint spoofing
- Inventing a Qwen consumer OAuth flow
- Vendoring CLIProxyAPI
- pea-pod marketing in this repository
- Claiming image generation works

If those stay true, **0.2.6 plus this docs cut is enough to call 1.0**. Extra adapters and `/v1/images` can land as 1.x.
