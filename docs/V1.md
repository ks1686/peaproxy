# v1.0 readiness

PeaProxy **v0.2.8** is already a shippable local gateway. A **1.0** tag is a honesty/quality cut, not a new OAuth program or a tray app.

**v0.2.8** (CLI parity with Catalog / Health / Request log / `accounts add` presets) is on `main` and is part of the shippable surface. Coordinator tags **`v1.0.0` on `main` after this docs PR merges** — this file does not claim that tag exists yet.

Related: [PLAN.md](PLAN.md) (phases), [PROVIDERS.md](PROVIDERS.md) (adapters), [OAUTH.md](OAUTH.md) (liability), [COMPETITOR-WINS.md](COMPETITOR-WINS.md) (issue themes vs shipped), [HARNESS.md](HARNESS.md), [CONFIG.md](CONFIG.md).

## Already shippable (0.2.x)

Do not rebuild these for 1.0:

- Live catalog (`ListModels` source of truth; hide is listing-only; optional pin/rename)
- OpenAI `/v1/chat/completions` + Claude `/v1/messages` (true SSE) + Codex `/v1/responses`
- Vision-in Showcase (URL / upload), image-out Showcase (real `/v1/images/generations`, not fake chat), and embeddings Showcase (real `/v1/embeddings`, not fake chat)
- Official **API-key** adapters and hosted/local OpenAI-compat presets
- Subscription **OAuth** for Claude, Codex, Gemini/Antigravity, xAI, Kimi, Meta Muse — **ToS/ban risk**; authors not liable; keys remain official
- OS keychain / encrypted-file secrets (no plaintext tokens in YAML)
- Round-robin / fill-first / sticky failover, retryable status + error-body skip, 30s cooldown, Health UI / `peaproxy health`
- Harness presets + `peaproxy clients verify [--chat]`
- Loopback default; LAN bind requires `--allow-lan` + admin token
- CLI + localhost UI only (**no tray, by design**)
- CLI parity with Catalog / Health / Request log: `peaproxy catalog pin|rename|hide`, `requests tail`, `health`, plus `accounts add` presets (**v0.2.8**)
- Settings, first-run Accounts CTAs, `config validate`, opt-in request inspector, persisted usage
- Tagged GitHub Releases (linux/darwin/windows, amd64+arm64)

Install: `go install github.com/ks1686/peaproxy/cmd/peaproxy@latest` (follows `main`; pin a tagged 0.2.x such as `@v0.2.8` if you do not want `@latest` to move).

## Known residuals (accepted in 0.2.x)

These are **not unmarked plan phases**. Call them out; do not hype them as done.

| Residual | Reality | 1.0? |
|---|---|---|
| Qwen consumer OAuth | Stub **not yet**. No CPA flow. Use `openai_compat` + a Qwen key. | **Do not block.** No new reverse-engineering unless a public flow exists. |
| Image-out | `POST /v1/images/generations` proxied for API-key OpenAI-compat adapters when the catalog tags `image_out`. Showcase one-click generates. Subscription OAuth does **not** invent an image path. | **Shipped (1.x).** |
| Claude Cloudflare 403 | Stock Go TLS. No uTLS / fingerprint spoofing. Prefer `adapter: anthropic` API key. | **Do not block.** Do not add uTLS for a 1.0 checkbox. |
| macOS / Windows tray | Not built. Locked: CLI + localhost UI. | **Won't do.** |
| Failover policies | `failover.policy`: `round-robin` (default), `fill-first`, `sticky`. Retryable HTTP 429/401/503/529 plus rate-limit / overloaded / auth-expired error bodies. Cooldown reasons omit raw bodies. | **Shipped.** |
| Amp WebSocket / `amp.url` | Custom URL chat-completions only. | **Won't do** as Amp management API. |
| Codex tools surface | Native Codex OAuth (`openai_oauth`) passes `tools`, `tool_choice`, and input items (`function_call`, `function_call_output`, `reasoning`) through `POST /v1/responses`; only `stream_options` is dropped. Chat clients on that account map tools / `tool_calls` / `tool` messages into Responses items and back. Other adapters round-trip function tools one level via chat completions. Translated SSE is not a full Responses tool event stream and does **not** execute tools. `image_gen` is not a `/v1/images/generations` proxy. | **Shipped (1.x leftover).** |
| Embeddings / quota-remaining APIs | `POST /v1/embeddings` proxied for API-key OpenAI-compat adapters when the catalog tags `embeddings`. Quota-remaining is **not** shipped. | Embeddings **shipped (1.x)**; quota later. |
| Copilot, Factory Droid, OpenCode Go sub | Not adapters. | Later, not 1.0. |
| GitHub Models | Retired 2026-07-30. | **Won't do.** |
| pea-pod.me page | Separate repo. | **Out of this repo.** |

## 1.0 cut checklist

A 1.0 tag is reasonable when **all** of the following are true. None of them require new OAuth reverse-engineering.

- [x] v0.2.8 product surface above is on `main` (CLI parity with Catalog / Health / Request log / `accounts add` presets, on top of the v0.2.6–v0.2.7 gateway)
- [x] Liability is documented in README, CLI, UI, and [OAUTH.md](OAUTH.md)
- [x] Docs match the 0.2.x shippable surface: README feature matrix, [PLAN.md](PLAN.md) phases, this file
- [x] CI green on the revision that will be tagged — **after this PR merges to `main` and CI is green on that commit** (coordinator tags from `main`, not from this branch)
- [x] Owner accepts the residual table: **YES** — standing full-product autonomy + ToS-risk OAuth override from owner Karim (2026-09-26); residuals stay as documented (Qwen not-yet, image-out shipped as 1.x, stock TLS, no tray)
- [x] Optional: refresh UI screenshots if Settings / Request log / onboarding should appear in README — live captures in `docs/screenshots/` (leftover #3)
- [ ] Optional: one **manual** OAuth smoke on a real subscription (cannot be CI). If Cloudflare 403, document “use API key” and still ship
- [ ] Tag **after** merge to `main`, not from a feature PR (`git tag -a v1.0.0` → GoReleaser)

## Won't-do for 1.0

- Menu bar / tray / TCC entitlements
- uTLS or TLS-fingerprint spoofing
- Inventing a Qwen consumer OAuth flow
- Vendoring CLIProxyAPI
- pea-pod marketing in this repository
- Inventing subscription-OAuth image-generation or embeddings hacks (use official API keys)

If those stay true, **0.2.8 plus this docs cut is enough to call 1.0**. Extra adapters can land as 1.x. Image-out landed as 1.x leftover #2. README screenshot refresh landed as 1.x leftover #3. Codex Responses tools pass-through landed as 1.x leftover. Embeddings (`POST /v1/embeddings`) landed as a 1.x leftover. Quota-remaining remains later.
