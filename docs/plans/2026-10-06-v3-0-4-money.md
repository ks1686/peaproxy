# v3.0.4 — the money findings

## Intent

`docs/V3.0.1-REVIEW.md` left five money findings open. v3.0.4 closes them, or
says plainly in code and docs what part of each remains outside a cap.

## Findings, verified against f453c1b

| # | Finding | Where it is true |
| --- | --- | --- |
| M1 | Ledger priced only when a provider volunteers `usage.cost` | `usage/parse.go` sets `CostUSD` from `usage.cost` only; published token counts are never priced against the deployment quote, so `priced < total` and the ceiling refuses forever. |
| M2 | No per-request reservation, so concurrent requests overshoot | `ceilingBlocks` reads `spentInWindow`; nothing is held between the check and the provider bill. |
| M3 | Exact-model routing bypasses `freeOnly` and the ceiling | Both are consulted only inside `pickAutomatic`; `routeResolved`'s non-automatic branch calls `g.route` and dispatches unfiltered. |
| M4 | `Price.Free()` ignores paid cache reads/writes | `catalog/pricing.go` checks `Input` and `Output` only. |
| M5 | Retrieval rounds' usage discarded | `gateway.go` proxy-tool loop returns only the final `resp.Raw`; earlier rounds were real billed calls. |

## Design

### M1 — price the ledger from published tokens

- `usage.Event.EstimatedUSD` — PeaProxy's own figure, derived from published
  token counts and the deployment quote. Separate from `CostUSD`, which stays
  the provider's own number and always wins when present.
- `usage.SpendWindow` struct replaces the three-value return so an estimated
  portion can be reported alongside the total instead of being quietly folded
  in. `usd` is reported + estimated; `priced` counts both.
- `Gateway.QuoteFor(account, clientModel)` resolves the deployment quote. For an
  exact model the upstream id is the client's id. For a `pea/*` route the
  account's candidate models come from that route's configured list intersected
  with the account's catalog rows; one candidate prices, several stay unknown.
  Unknown is the answer whenever the deployment is not unambiguous.
- Pricing uses `Quote.ExpectedCost`, which is only `ok` when every component the
  call touched was quoted. A call that read cache on a quote with no cache rate
  stays unpriced rather than being under-priced.
- **Nested cache reads.** OpenAI reports `cached_tokens` inside the prompt
  count; Anthropic reports `cache_read_input_tokens` beside it. Pricing both the
  prompt total and the cache total double-counts OpenAI's cached tokens, so
  `usage.Event.CacheReadNested` records which shape was seen and nested reads
  are subtracted from the uncached input before pricing.
- `config.PriceQuote` gains optional `cacheRead` / `cacheWrite`. A configured
  quote without them can only price calls that never touch the cache.

### M2 — reservation

- `usage.Store.Reserve(usd)` holds an in-flight estimate; `Settle(reserved)`
  nets it against the event that lands when the call finishes, in one locked
  step, so a completed call is counted once and an in-flight one is counted
  early.
- The estimate prices what is knowable before the answer exists: the request's
  own input tokens. Output length is not knowable, so it is reconciled on
  completion instead. The ceiling therefore caps input-side spend plus settled
  actuals; concurrent in-flight output remains outside the cap, bounded by
  `requestEngine.maxInFlight`.
- Check and reserve happen under the store's lock, so N concurrent requests
  cannot all pass the same reading.

### M3 — exact models consult the refusals

`routeResolved`'s exact branch filters candidates through the same
`FreeOnly` / ceiling logic `pickAutomatic` uses. Local-tier deployments stay
exempt: they run on this machine and cost nothing.

### M4 — a published cache rate that is not zero is not free

`Price.Free()` returns false when `CacheRead` or `CacheWrite` is published and
nonzero. Unpublished stays acceptable, because refusing every deployment whose
provider does not document cache pricing would disable free-only routing
entirely — and the certainty the ledger needs is enforced by `ExpectedCost`
instead.

### M5 — retrieval rounds reach the ledger

The proxy-tool loop records each completed intermediate round as its own event
through the same store, so a two-round search is two priced calls.

## Gate

- Every fix gets a regression test that fails against f453c1b (mutation check:
  revert the fix, watch it fail).
- Eval scenarios gain crossed rates so an input-only economy comparison cannot
  pass the gate, plus promises for the exact-model refusals.
- `PEAPROXY_SECRET_BACKEND=file go test ./...`

## Left open, stated in docs

Output spend from concurrent in-flight requests is reconciled, not capped. A
configured quote without cache rates cannot price cached calls. The eval gate
still checks behaviour, not mutations; a mutation harness is follow-up work.
