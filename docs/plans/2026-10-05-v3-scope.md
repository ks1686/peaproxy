## Defects and evidence

### D1 — repeated live stream failure; release blocker

User repeatedly reported `stream ended without finish_reason`, then a retry failure while the plan was being written. No exact retry error text supplied. See [incident record](2026-10-05-v3-stream-incident.md). Actual wire, upstream and root cause remain unverified. T1 owns reproduction, repair and affected-client validation. Keep retry failure as a related symptom until traced, not a confirmed second cause.

### D2 — native stream usage undercount; reproduced at parser level

`internal/usage/parse.go` only decodes top-level usage and replaces rather than merges stream samples. Isolated tests at baseline produced:
- Anthropic message_start input=12 followed by message_delta output=7 → input=0/output=7.
- Responses response.completed containing response.usage input=12/output=7 → usage unknown.

T2 adds permanent wire fixtures and verifies server integration. This does not establish the cause of D1.

### D3 — cache counters ignored; reproduced

ApplyPublishedUsage with prompt_tokens=100 and prompt_tokens_details.cached_tokens=80 leaves Event.CacheRead=0. CacheRead/CacheWrite exist in usage structs but the published-usage parser does not populate them. T2 owns provider-specific parsing and accounting.

### D4 — automatic routing misses simultaneous model cooldowns; reproduced

`internal/gateway/engine_route.go` snapshots slots.anyActive, which chooses only one active slot. With model `other` cooling for one minute and `m` for one hour on acct-a, pickAutomatic still includes acct-a/m. T1 must test every candidate against its own cooldown; verify actual attempt behavior separately.

### D5 — free eligibility uses another account's price; reproduced

priceFor looks up model ID without deployment/account identity. Catalog rows acct-a/m priced zero and acct-b/m priced 4 cause automaticKind(pea/free, acct-b/m) to return true. Reproduced eligibility error, not a claim that an actual bill occurred. T3 scopes quotes and T6 tests end-to-end routing and fallback.

### D6 — cache optimization rewrites unrelated request bytes; code finding

`internal/promptcache/policy.go` insertBreakpoint unmarshals/remarshals the complete request through maps. This changes formatting/order outside the inserted marker. Token/cache impact requires measurement; T7 adds exact preservation fixtures before repair.

### D7 — automatic affinity binding deserves regression coverage; suspicion

pickAutomatic reads affinity under the route alias while ordinary success bookkeeping receives the resolved model. Trace all success paths and prove model+deployment stability with two models on one account. Do not mark confirmed until reproduced. T6 owns this investigation.

## Research inputs and limits

- Headroom (Apache-2.0): https://github.com/headroomlabs-ai/headroom — proxy retrieval and stable cache-oriented transformations.
- context-mode (ELv2): https://github.com/mksglu/context-mode — local artifacts, lexical retrieval and deterministic processing. Do not copy ELv2 code into MIT sources.
- LiteLLM: https://docs.litellm.ai/docs/routing — deployment pools and quotas.
- OpenRouter: https://openrouter.ai/docs/guides/routing/provider-selection — capability, privacy, price and health gates.
- RouteLLM: https://github.com/lm-sys/RouteLLM and https://github.com/vllm-project/semantic-router — quality/cost routing evaluation.
- RTK: https://github.com/rtk-ai/rtk — structured output reduction; optional client integration only.
- LLMLingua: https://github.com/microsoft/LLMLingua — research reference, not a default dependency.
- Free-provider discovery: https://github.com/0xzr/freellmpool — candidate source, not authority for terms or quotas.

Provider prices and terms found during research are snapshots. Revalidate official documentation, model catalog and account entitlements in T4; never embed headline savings percentages as guarantees.
