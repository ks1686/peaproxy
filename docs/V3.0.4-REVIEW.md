# v3.0.4 — the money findings, and the correctness findings

`docs/V3.0.1-REVIEW.md` left fourteen findings open. This release closes the
five money ones **and all seven correctness findings** that were still open, so
the tree ships as one verified release rather than a set of fragments. Each
claim below was checked against the code at `f453c1b`, and each fix was
mutation-verified: the fix was reverted and the regression test had to fail.

Two of those deserve a note, because the fix was not the obvious one.

**Anonymous is not the same as "no API key."** Every OAuth adapter reports no
API key whether or not it holds a valid session, so the first definition written
— read the adapter's own `Capabilities().APIKey` — would have refused every
Copilot-, Claude- and Codex-hosted account the moment the guard landed. It asks
now whether *any* credential is attached: no key, no key env, no configured
OAuth session. A configured OAuth session whose token has expired also counts as
an account, because that failure is a login that needs refreshing and reporting
it as an anonymous endpoint sends the user looking in the wrong place.

**Warmth is only consulted for candidates price did not already pick.** The gate
caught this in my own new scenario: with the warm deployment declared first, the
scenario passed whatever the warmth code did, because warmth was never asked.
Both scenarios now declare the cheaper deployment first, so warmth is reached.

### The gate now tries to break itself

`TestRoutingPromisesWouldNoticeTheirOwnRegression` takes each routing promise,
breaks the guard that promise depends on, and requires the promise to fail. It
edits the working tree while it runs (restored in a `defer`, verified on the way
back in, and skipped under `-short`), and it rejects a mutation that fails to
compile — a scenario that fails because nothing ran has proved nothing.

This exists because the naive version of the test is worthless: editing a source
file while the test binary that would exercise it is already compiled changes
nothing at all, so the mutation has to be recompiled in a subprocess. It also
exists because a scenario whose guard drifts out from under it should fail
loudly. Each mutation names an exact anchor that must appear **exactly once**;
zero matches — code moved, or already changed — fails the gate instead of
silently passing.

Two things were found while building this and fixed rather than documented around:

- **Cached tokens were going to be billed twice.** OpenAI counts `cached_tokens`
  inside the prompt total; Anthropic counts `cache_read_input_tokens` beside it.
  Pricing both the prompt total and the cache total charges OpenAI's cached tokens
  at the full input rate a second time. The provider's shape is now recorded
  (`cacheReadNested`) and nested reads are taken out of the uncached input first.
- **A configured quote could not price a cached call at all.** `config.PriceQuote`
  had no cache fields, so every cached call on a user-configured deployment would
  have stayed unmeasured — and prompt caching is on by default. `cacheRead` and
  `cacheWrite` are now optional fields.

## What the ceiling is, precisely

A ceiling refuses when recorded spend cannot be measured. That is unchanged and
is the safe direction. What changed is that far more spend *can* be measured, so
the guard is a ceiling rather than an outage.

It is still not a hard cap, and the limit is stated rather than implied:

- Output spend from requests that are in flight at the same time is reconciled
  after the fact, not prevented. Output length is unknowable before the model
  answers. The overshoot is bounded by `requestEngine.maxInFlight`.
- Reservations are taken at `admitted`, the point every chat, Responses,
  Messages and **embeddings** attempt passes through. **Image calls still do not
  reserve or take a slot.** Images are not billed per token, so a token-bound hold
  would mean nothing for them; that is stated rather than half-fixed.
- A deployment nobody has priced holds nothing, because a hold is computed from a
  published rate and inventing one would charge a ceiling for a figure PeaProxy
  made up. Routing still checks unpriced deployments against the ceiling before
  selecting them — they are never treated as free — so what remains is the
  concurrent burst, not the ordinary single request. This is the one money gap
  left open here.
- Reservations are input-side only, and are bounded above by the request's byte
  length rather than estimated from a tokenizer. They over-reserve by design.
- A call whose usage was published on one side only, or that touched the cache on
  a quote with no cache rate, stays unmeasured and makes the ceiling refuse.

## Open, unchanged

Nothing from the v3.0.1 correctness list is left open. Three items remain, none
of which are code findings:

- **Retrieval savings are not quantified.** The discarded rounds are now recorded,
  so the ledger can be read; the saving itself still has to be measured against a
  real workload.
- **D1 is verified by fixture only.** The route-rewriter flush is covered by tests
  that drive the real paths with a fake upstream, not by a live provider.
- **The Cursor adapter is blocked** on account quota, and is separate work when
  that resets.

One finding did not reproduce: v3.0.1 recorded the UI smoke's `#preset` locator
as no longer matching after the Policy page was added, "silently skipping an
assertion". It matches, the assertion runs, and the smoke passes — 4 groups, 37
presets. Making the assertion impossible fails the smoke loudly, so it is not
skipping. That finding is closed as not reproducible rather than left standing.

`PEAPROXY_SECRET_BACKEND=file go test ./...` (including the mutation gate),

## Honest summary

The largest remaining gap in v3.0.1 — a ceiling computed over a ledger that most
providers left empty — is closed, and the ledger now says which parts are a bill
and which are PeaProxy's own reading of one. All fourteen findings are closed or
explicitly not reproducible. What the ceiling does not prevent is stated above, in
the same place a user will read it, and the money guards now live in the eval
gate rather than in unit tests that can be satisfied without trying.
