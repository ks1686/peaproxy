# PeaProxy v2 request engine

This is the v2.0.0 request engine. It does not change the schema version.

The request path is still: read the body, keep the exact model unless the caller named an enabled automatic route, choose an account, call the native adapter or a translation, and stop once a stream event is committed.

What changed:

- One attempt budget and deadline cover the whole request. Image calls are not replayed after an uncertain delivery.
- Streams are checked for a valid first event before that event is forwarded. A later failure stays on the same response.
- Cooldowns can name one model. Another model on the same account stays eligible. A cooled account is not probed again until the cooldown ends, and then only one request is the first probe.
- Credential refresh for a single OAuth account is one in-flight call. A newer login is not overwritten by a late refresh.
- `promptCache` defaults to preserve. Optimize adds a breakpoint only for the documented Anthropic profile.
- `pea/auto`, `pea/economy`, `pea/local`, and `pea/free` do nothing until `automaticRoutes.enabled` is true. Exact model ids are not rewritten.
- Response and embedding caches are off unless the matching config flag is set. Cached values stay bound to the account, endpoint, and model.
- `peaproxy clients detect|connect|disconnect|status` edit only the PeaProxy block in OpenCode, Pi, Continue, Codex, and Claude Code configs. Pass `--root` so a command does not touch the real home directory.
- `GET /admin/engine` reports attempt, cache, and route settings without secrets. Client connect and disconnect reject a foreign `Origin` and an unknown name.

Compatibility metadata, when loaded, cannot invent catalog model ids. Unsigned or incompatible metadata is refused and the last good document stays in place. Remote auto-update is off.

Installed harness versions were not live-tested. A fixture or UI smoke that passes does not mean a particular OpenCode, Claude Code, Continue, Codex, or Pi release is supported.

See [CONFIG.md](CONFIG.md) for the fields and [COMPATIBILITY.md](COMPATIBILITY.md) for the metadata rules.

## v2.0.10

- The Pi preset is a `~/.pi/agent/models.json` that overrides the built-in `anthropic` (no `/v1`) and `openai` (`/v1`, Responses) providers, so pi keeps its bundled model metadata. The old preset exported `ANTHROPIC_BASE_URL` / `OPENAI_BASE_URL`, which pi never reads. `clients connect pi` now writes those two overrides (merging into existing entries) instead of printing the snippet, and `disconnect pi` removes only fields it owns. Live-verified with pi 0.87.1 on both wires, including tool calls. See [HARNESS.md](HARNESS.md).
- `clients connect` for JSON configs could drop the closing brace when the same file was edited more than once (a slice-capacity aliasing bug in the key-preserving writer); fixed.
- The OpenCode preset declares per-model `limit`, `modalities` and `variants`, uses `@ai-sdk/openai` for GPT, and keeps `peaproxy-*` provider ids. See [HARNESS.md](HARNESS.md).
- An OpenAI-wire client on a Claude account no longer receives `finish_reason` + `[DONE]` after the upstream stream failed mid-turn.

## v2.0.9

- The client's `anthropic-beta` header is forwarded to Anthropic, merged after PeaProxy's own betas (both `anthropic` and `anthropic_oauth`). OpenCode's adaptive thinking sends `thinking.block_binding` (captured on Claude Opus 5.5), which Anthropic rejects without the `thinking-binding-controls-2026-08-01` beta the client asked for. Opus 5.5, Sonnet 5 and Fable 5.1 tool calls from OpenCode were live-verified on an Enterprise OAuth account. Names are checked at the HTTP boundary (letters, digits, `-_.`; at most 16, 64 characters each); anything else is dropped. `anthropic_oauth` never forwards `context-1m-*` (the subscription lane rejects it without extra usage, as before), and `anthropic` never forwards `oauth-*` (it conflicts with `x-api-key`).

## v2.0.8

- Claude subscription OAuth on a Team/Enterprise workspace no longer rejects OpenCode as a third-party app (as of 2026-09; the classification is Anthropic's and can change) ("Third-party apps now draw from extra usage"). OpenCode's core tools are sent under Claude Code's names (`bash` → `Bash`, `read` → `Read`, …) and renamed back in responses. See [OAUTH.md](OAUTH.md).

## v2.0.7

- `preludeTimeout` defaults to 30s (was 5s). A slow first event moves to the next account only when another can take the request, never retries the same account, and never starts a cooldown. The last reachable account is bounded by `deadline` alone.
- Cooldowns last 30s or the upstream's reset hint (`Retry-After`, or the Antigravity / Cloud Code error body), clamped to 1s–1h. A transport failure (502, 504, edge connect error 503) is retried once and cools for only 5s. The 503 names each cooled account and its cause. The `Retry-After` sent to clients is capped at 60s.
- OAuth tokens above the macOS keychain item limit are stored as chunked keychain items, header written last. An unreadable stored secret is treated as absent with a stderr warning; only that account logs in again. One account's failed secret write no longer stops the others from being saved. Chunks left by an interrupted save are swept by a later write.
- Translated `/v1/messages` streams emit tool calls as `tool_use` blocks, carry usage, report `max_tokens` on truncation and `refusal` on a content filter, and end with an `error` event (never a completed tool turn) when the upstream breaks off mid-stream. While tool arguments buffer, a `ping` is sent when a tool-call delta arrives and at least a second has passed since the last event.
- Antigravity: tool calling both directions, tool schemas reduced to the Gemini Schema proto (tuple `items` included), `gemini-3.1-pro-high` / `gemini-3-pro-high` sent as `gemini-pro-agent`, 429 / 503 capacity errors cool only that model, and safety stops finish as `content_filter`.
- Finishing an OAuth login from the web UI refreshes the catalog. An older catalog refresh that finishes last no longer replaces a newer one.
- The account a request is attributed to is the last one actually called. Cooldown errors also name accounts that are between cooldown and their recovery probe.

Known limits:

- A JSON Schema with both a type list and `anyOf` is widened to their union for Gemini.
- A keychain reader racing another process's token rewrite retries up to 3 times.
- Chunks left by an interrupted save are swept only once they are 30 minutes old, so a save in another process sharing the config directory is never disturbed.
- `secrets.index` is not locked across processes, so a server and a `peaproxy auth login` saving at the same moment can drop each other's cleanup entries; the orphaned chunks stay in the keychain but are never read.
- Gemini `promptFeedback.blockReason` (a blocked prompt with no candidates) still finishes as `stop`.
- An array schema with no `items` whose `anyOf` has several branches carrying `items` is still rejected by Cloud Code.
- `gemini-3.1-pro-high` → `gemini-pro-agent` was not live-verified on the release binary (weekly quota exhausted); `gemini-3-pro-high` and the flash models were.
- The user-reported 429 was not reproduced directly. The cooldown cascade and the Cloud Code throttle blackouts were.
